SafeCore 1.0.0 · macOS installer

One DMG, one double-click, no Terminal

Today a SafeCore box is set up by typing five sudo commands. The plan is to wrap all of them in a branded SafeCore app inside a universal DMG. The operator enters the five enrolment details in a form and approves one macOS password prompt. The app does the rest.

SafeCore-1.0.0.dmgSigned and notarized disk image. Runs on Apple silicon and Intel Macs.
SafeCore.appInstalls, enrols and controls the box. The developer's .pkg is bundled inside the app.
build-dmg.shOne script that rebuilds the DMG when the developer sends a new version, e.g. 1.0.1.

Universal

What “universal” means here, and the one risk

In my control

The DMG and the SafeCore app

  • Built with arm64 + x86_64 slices, so one file runs natively on Apple silicon and Intel.
  • Signed with Developer ID and the hardened runtime, then notarized and stapled, so Gatekeeper opens it with no warnings, even offline.
  • Minimum macOS version to be confirmed (question 5 below).
Depends on the developer

The SafeCore binaries inside the .pkg

  • safecored and safecore-setup are Rust builds from target/release, which usually produces one architecture only.
  • The first build step lists the architectures of every binary in the package with lipo -archs.
  • If they are arm64 only, Intel Macs cannot run them because Rosetta only translates in the other direction. The fix is for the developer to also build x86_64-apple-darwin and merge the two builds with lipo. Until then, the app tells Intel users that their Mac is not supported yet and stops before installing anything.
Build pipeline

How the DMG gets made, in order

  1. Fetch and verify the packageGet SafeCore-1.0.0.zip from Bitbucket, unzip it into an isolated folder and record its SHA-256 checksum.
  2. Inspect the .pkgExpand the package with pkgutil --expand-full, read its install scripts, and check the architectures of every binary.
  3. Build SafeCore.appSwiftUI app plus a small privileged helper that runs only the six commands in the table above. It is built universal with Xcode.
  4. Bundle and signPlace the .pkg in the app's Resources folder, then code-sign the helper and the app with a Developer ID Application certificate.
  5. Make the branded DMGAdd the background artwork from the mockup, the window size and the icon position, then compress the image (UDZO format).
  6. Notarize and stapleSubmit with xcrun notarytool submit --wait, then staple the ticket to the DMG.
  7. TestRun a fresh install and an upgrade on Apple silicon, an install on Intel (or check that the refusal message appears), a wrong access key, and all four control buttons.

All seven steps are wrapped in build-dmg.sh. For a new release, you point it at the new zip and get a new signed DMG.

Before I start

Six things I need from you or the developer

01
Access to the packageThe Bitbucket link returns “401 unauthorised” without a login. Download the zip into the SafeCore-v1 folder, or share a Bitbucket app password.
02
Can safecore-setup run without prompts?Ask the developer whether it accepts flags or environment variables, for example --tenant-id. If not, I need the exact order of its prompts and any yes/no confirmations it asks.
03
Apple Developer accountSigning and notarizing need a Developer ID Application certificate and an App Store Connect API key. Without them, macOS will warn that the app “cannot be opened” on every box.
04
Intel supportShould Intel Macs be supported now? If yes, the developer needs to send x86_64 builds, or I can merge them if they send both.
05
Minimum macOS and defaultsThe lowest macOS version the boxes run, and whether the config API endpoint and domain should come pre-filled.
06
Status output formatA sample of safecorectl status output, so the tiles show the right numbers for services, models and cameras.
